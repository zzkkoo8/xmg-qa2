# V1 分阶段交付与验收

日期：2026-09-05。本文是产品实施路线，不冒充已由 Spec Kit 生成/批准的 Feature spec、plan 或 tasks；具体 Feature 仍按仓库官方流程创建。

V1 定义见[需求基线](../requirements/REQUIREMENTS-BASELINE.md)。“第一个 Feature 完成”和“V1 发布完成”不同，真实集成与恢复测试不能被放到 V1 之外。

## 1. Feature 顺序

下列 003–008 为建议编号，创建时由 Spec Kit 检查分支/规格占用后分配。本轮将问答控制与质量评测提前，保留 Admin/模板交付阶段；历史建议编号不是已创建 Feature。

| Feature | 产物与关联需求 | 可独立验收 | 必须停止并记录的阻塞 |
| --- | --- | --- | --- |
| 003 问答骨架与最小运行基础 | 问题理解/路由、AnswerDraft/Check、合成场景与评测结构；持久任务/ResumeAttempt、API、PG/图/broker、Fake 合约；Chat/Admin 壳、最小本地认证/ACL、开发 Compose/镜像/CI；FR01/05/12/13/14/17/18–20 基础 | ≥20 个合成控制场景验证直答/检索/补充/无进展；API 创建→等待→重启→恢复；并发/定向恢复；登录与任务页真实串接；干净构建 | 版本组合失败；恢复协议不成立；开发环境依赖不可用 |
| 004 真实高质量问答闭环 | Dify Adapter、Evidence/claim、真实模型、检索恢复/证据包、答案检查、质量对照报告、外发 Policy；FR02/06/07/08/10/18–20 | ≥100 条冻结回归题集与单次 RAG 对照，报告正确性/覆盖/合理求助和费用；真实检索/生成；无结果/鉴权失败/故障分类；客户隔离 | Dify 地址/版本/权限、模型凭证、测试题集缺失 |
| 005 自主调查与只读取证 | Registry/YAML、官方 web provider、一类真实产品只读 API/MCP、按缺口选动作与更新假设；FR03/04/07/11/19/20 | 动作轨迹回归含换源/反证/无进展；配置更换优先级；至少一次真实知识不足→工具取证→再判断；所有写动作拒绝 | 目标系统没有可验证只读接口/账户，不得用 Fake 充数 |
| 006 钉钉、Chat 与人工闭环 | Stream Adapter、幂等通知、完整 Chat、日志补充、固定内置报告；FR01/05/09/10/13 | 真实钉钉创建→工程师回传→继续调查；Chat 流式/重连/引用/取消/下载；通知失败恢复 | 应用权限/收件映射/持久发送 API 未配置 |
| 007 Admin、模板与展示扩展 | 连接/能力/工作流发布、账号权限审计、HTML/MD 模板、主题、构建期 UI 注册；FR03/07/10/11/14/15/16 | 配置/模板发布回退；旧 Case/报告版本固定；禁用能力生效；XSS/模板越权拒绝 | Renderer/权限隔离失败；版本发布绕过策略 |
| 008 分发发布联合验收 | Release/OCI/在线配置/每平台离线包、迁移/备份/回退、观测、评测；全部 FR | 干净主机在线/断网安装；完整真实链路、72 小时等价等待、SLO/回退；无 Node 部署 | 任一真实接入缺失、安全失败、恢复丢案、离线镜像不全 |

优先完成问答骨架、真实答案质量基线和自主调查，再完善入口/控制台/模板/发布。基础认证、持久化和构建从开始就做，不能以“问答优先”删掉可靠性或既有 V1 要求。

Fake 阶段是便于验证领域与恢复机制的内部里程碑，不能对外宣称“V1 已完成”。

## 2. 开始每个 Feature 的固定步骤

1. git status、确认 main 最新远端状态和可回退基线；新 Feature 分支，禁止在 main 写。
2. 读取需求基线、相关 Contract/ADR、当前开发门禁。
3. 通过官方 $speckit-specify 建 spec，完成 clarify；已知选择和默认值直接复用，不重复访谈 Q1–9。
4. Plan 冻结包版本/镜像、数据与错误 Schema、迁移、预算、测试环境、具体文件及回退。
5. Checklist → Tasks → Analyze；Critical/High 未清零不得实现。
6. 获得当前 Feature 业务编码授权后按 Task 实施；用真实验证证据完成 converge。
7. 独立提交、推送、PR/CI；合并依据当次用户授权与仓库规则，不假定本文自动授权所有 Feature。

## 3. 版本兼容验证清单

先在测试环境固定 Python 3.12、目标 PostgreSQL 主版本、FastAPI/Pydantic、SQLAlchemy/psycopg、LangGraph/checkpoint-postgres、Celery/Kombu/RabbitMQ 和 MCP SDK/协议组合，生成 uv.lock 与镜像 digest。

必须验证：checkpoint schema 初始化、interrupt/resume、同步持久化、Worker event loop/进程生命周期、连接池不跨 fork 错用、取消与重试、模型结构化响应、钉钉 SDK 重连。不得直接把 README 最新标签当作已兼容组合。

前端固定 Node LTS/pnpm、React/Vite、Tailwind/shadcn primitive、TanStack、assistant-ui 和生成客户端版本，提交 lock；同时验证 pwdlib/PyJWT、模板 renderer/sanitizer 与基础镜像平台。不因开发机组件冲突升级其他项目的 Node/npm 或共享 Docker。

SDK、PyPI、容器标签可不同；冻结实际安装渠道和 SHA。无充分依据不使用预发布特性，不重写 vendored Spec Kit 脚本。

## 4. 端到端验收场景

| 场景 | 预期结果 |
| --- | --- |
| 产品 FAQ，内部知识足够 | 不无意义调用全部工具，答案引用匹配版本 |
| KB 空结果 | 升级适用能力或请求补充 |
| KB 401 / 服务不可达 | 分别显示授权问题/服务问题，不能说“产品不支持” |
| 内部旧文档与新版官方资料冲突 | 识别版本/命题差异，不机械按来源排名 |
| 工具建议 restart/写 API/任意 shell | 运行时拒绝；可生成给人的建议但不执行 |
| 未授权客户 dataset/报告/恢复 | 在模型、重排和输出前拒绝访问 |
| 需要三项日志，只回传两项 | 已回传内容保留，明确仅缺第三项，仍等待 |
| 暂停三天后 Worker/服务重启 | 通过同 runtime_key 恢复，历史证据与版本未丢 |
| 重复钉钉事件/恢复事件/双 Worker | 一案一有效执行，状态/输出不重复 |
| checkpoint 与业务状态中间崩溃 | StepCommit/operation_id 对账恢复，无已成功结果重复落库 |
| 人工回复已被图消费但回执未落库，随后又到下一 interrupt | 重投旧恢复事件仅补 ResumeAttempt 回执，不误恢复下一等待；无法确认时明确暂停 |
| 新图无法加载旧检查点 | 明确暂停，旧镜像完成或显式迁移 |
| 通知已发送但回执丢失 | DELIVERY_UNKNOWN，不无限重复提醒 |
| 外部搜索/模型/观测尝试带出秘密 | 请求前拦截/脱敏，遥测与 broker 不含凭证 |
| 连续无新增证据或预算耗尽 | 阶段总结 + 暂停/人工协助，无法绕过上限 |
| PostgreSQL/队列故障后恢复 | 不丢已 ACK 输入；已持久 Outbox 可重投 |
| 取消发生在模型/工具请求中 | 记录在途动作，取消后不再发布旧结果或发新动作 |
| Chat 刷新、SSE 断线、游标过期 | 从任务快照恢复/补事件；不新建 Case 或重新发起模型调用 |
| viewer 请求 Admin API、伪造身份头、CSRF、注销会话 | 后端拒绝；角色变更与会话撤销及时生效 |
| 工作流/模板同时编辑、发布与回退 | 版本冲突明确；旧 Case/报告不漂移；禁用能力仍立即检查 |
| 自定义 HTML/MD 企图执行脚本、访问文件/网络或超限渲染 | 清洗/隔离/资源限制生效，失败不污染最终报告 |
| 断网安装、架构错误、重复安装、升级后回退 | 镜像清单完整；错误阻止启动；不删除数据卷；按 schema 兼容或一致备份恢复 |

## 5. 评测与运维验收

评测从 003 的合成控制场景、004 的真实答案基线开始，不等到 008 才发现不会答题。采用不少于 100 个独立冻结的工程师标注题目，覆盖 FAQ、版本冲突、部署失败、网络/WAF 故障、日志分析、资料不足、拒绝越权、工具故障和多轮恢复。数据分开发集/冻结回归集，避免只评调过提示词的题目。

记录产品/版本、必需事实、正确来源、可接受建议、应升级/拒答标签。比较相同题集下的知识命中、引用支持、任务成功、正确转人工、延迟与费用；LLM-as-judge 固定模型/提示词并人工抽样，不以单一 Ragas 分数裁决发布。

SLO 在需求基线中，质量指标分母、门槛和人工判定见[问答质量](../governance/ANSWER-QUALITY.md)；达不到时报告样本、外部依赖和失败类型，不删题提升成绩。发布前必须有 Compose 健康检查、迁移前备份、恢复演练、旧图/旧镜像兼容策略、凭证撤销和人工接手流程。
