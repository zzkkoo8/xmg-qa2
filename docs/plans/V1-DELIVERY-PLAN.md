# V1 分阶段交付与验收

日期：2026-09-05。本文是产品实施路线，不冒充已由 Spec Kit 生成/批准的 Feature spec、plan 或 tasks；具体 Feature 仍按仓库官方流程创建。

V1 定义见[需求基线](../requirements/REQUIREMENTS-BASELINE.md)。“第一个 Feature 完成”和“V1 发布完成”不同，真实集成与恢复测试不能被放到 V1 之外。

## 2. 开始每个 Feature 的固定步骤

1. git status、确认 main 最新远端状态和可回退基线；新 Feature 分支，禁止在 main 写。
2. 读取需求基线、相关 Contract/ADR、当前开发门禁。
3. 通过官方 $speckit-specify 建 spec，完成 clarify；已知选择和默认值直接复用，不重复访谈 Q1–9。
4. Plan 冻结包版本/镜像、数据与错误 Schema、迁移、预算、测试环境、具体文件及回退。
5. Checklist → Tasks → Analyze；Critical/High 未清零不得实现。
6. 获得当前 Feature 业务编码授权后按 Task 实施；用真实验证证据完成 converge。
7. 独立提交、推送、PR/CI；合并依据当次用户授权与仓库规则，不假定本文自动授权所有 Feature。

## 3. 版本兼容验证清单

先在测试环境固定 Python 3.12、目标 PostgreSQL 主版本、FastAPI/Pydantic、SQLAlchemy/psycopg、LangGraph/checkpoint-postgres、Celery/Kombu/RabbitMQ 和 MCP SDK/协议组合，生成 uv.lock 与镜像 digest。

必须验证：checkpoint schema 初始化、interrupt/resume、同步持久化、Worker event loop/进程生命周期、连接池不跨 fork 错用、取消与重试、模型结构化响应、钉钉 SDK 重连。不得直接把 README 最新标签当作已兼容组合。

SDK、PyPI、容器标签可不同；冻结实际安装渠道和 SHA。无充分依据不使用预发布特性，不重写 vendored Spec Kit 脚本。

## 4. 端到端验收场景

| 场景 | 预期结果 |
| --- | --- |
| 产品 FAQ，内部知识足够 | 不无意义调用全部工具，答案引用匹配版本 |
| KB 空结果 | 升级适用能力或请求补充 |
| KB 401 / 服务不可达 | 分别显示授权问题/服务问题，不能说“产品不支持” |
| 内部旧文档与新版官方资料冲突 | 识别版本/命题差异，不机械按来源排名 |
| 工具建议 restart/写 API/任意 shell | 运行时拒绝；可生成给人的建议但不执行 |
| 未授权客户 dataset/报告/恢复 | 在模型、重排和输出前拒绝访问 |
| 需要三项日志，只回传两项 | 已回传内容保留，明确仅缺第三项，仍等待 |
| 暂停三天后 Worker/服务重启 | 通过同 runtime_key 恢复，历史证据与版本未丢 |
| 重复钉钉事件/恢复事件/双 Worker | 一案一有效执行，状态/输出不重复 |
| checkpoint 与业务状态中间崩溃 | StepCommit/operation_id 对账恢复，无已成功结果重复落库 |
| 人工回复已被图消费但回执未落库，随后又到下一 interrupt | 重投旧恢复事件仅补 ResumeAttempt 回执，不误恢复下一等待；无法确认时明确暂停 |
| 新图无法加载旧检查点 | 明确暂停，旧镜像完成或显式迁移 |
| 通知已发送但回执丢失 | DELIVERY_UNKNOWN，不无限重复提醒 |
| 外部搜索/模型/观测尝试带出秘密 | 请求前拦截/脱敏，遥测与 broker 不含凭证 |
| 连续无新增证据或预算耗尽 | 阶段总结 + 暂停/人工协助，无法绕过上限 |
| PostgreSQL/队列故障后恢复 | 不丢已 ACK 输入；已持久 Outbox 可重投 |
| 取消发生在模型/工具请求中 | 记录在途动作，取消后不再发布旧结果或发新动作 |

## 5. 评测与运维验收

采用不少于 100 个工程师标注题目，覆盖 FAQ、版本冲突、部署失败、网络/WAF 故障、日志分析、资料不足、拒绝越权、工具故障和多轮恢复。数据分开发集/冻结回归集，避免只评调过提示词的题目。

记录产品/版本、必需事实、正确来源、可接受建议、应升级/拒答标签。比较相同题集下的知识命中、引用支持、任务成功、正确转人工、延迟与费用；LLM-as-judge 固定模型/提示词并人工抽样，不以单一 Ragas 分数裁决发布。

SLO 和指标口径在需求基线中；达不到时报告样本、外部依赖和失败类型，不删题提升成绩。发布前必须有 Compose 健康检查、迁移前备份、恢复演练、旧图/旧镜像兼容策略、凭证撤销和人工接手流程。
