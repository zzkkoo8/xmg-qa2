# xmg-qa2 需求基线

版本：1.2；日期：2026-09-05；状态：本轮授权形成的设计基线；强化问答核心与质量评测，保留 Web/分发/模板需求，尚未执行运行时编码门禁。

受众：产品负责人、实施工程师、Codex。本文是产品需求唯一入口；设计细节分别归属 Architecture、Workflow、Contracts，禁止另起一份不同的 V1 定义。

## 1. 产品目标

xmg-qa2（小马哥数字人）首先是高质量问答 Agent，集中部署为数字技术支持工程师。核心目标是理解所问、产出正确且可行动的答案，并在证据不足时自主推进调查。Web、任务管理、插件、模板和部署服务于这一目标。它融合产品知识与通用 IT 能力，理解问题、提出假设、寻找和验证证据、调用获准能力、请求现场配合，最后给出可追溯答案或报告。问题可以跨多轮、跨数天处理。

系统应持续寻找能推进问题的下一步，同时遵守只读权限、数据范围、时间、调用和成本上限。不能把“穷尽办法”实现成无限循环，也不能只完成一次 RAG 检索就放弃。

## 2. 用户已确认的选择

| 问题 | 选择 | 正式要求 |
| --- | --- | --- |
| Q1 | C | V1 为真实垂直闭环 MVP；Fake 只用于测试，不能作为 V1 成功标准 |
| Q2 | 自定义 | 产品知识 + 通用技术；支持内部/外部知识、插件、脚本、Skill、API、MCP、验证和报告 |
| Q3 | A | 只读调查与建议；不自主修改生产系统；遇错、卡住或缺现场条件时暂停并请求人工协助 |
| Q4 | B | 每个问题有持久 SupportTask，可跨天暂停、补充和恢复 |
| Q5 | B | 根据权威性、版本、时效、直接性、验证状态、相互一致性动态裁决证据 |
| Q6 | B | 允许受控公网检索；查询、第三方模型、遥测等全部外发通道受脱敏及授权范围限制 |
| Q7 | 用户纠正 | 核心是可编排能力与优先级：知识不足可进一步调用 API/MCP/获准设备诊断，最后求助人类；不是固定复杂度分档 |
| Q8 | B | YAML/JSON 配置工作流与能力优先级；成熟开源优先，V1 不做拖拽编辑器 |
| Q9 | B | 中央 API + Worker；V1 单机 Docker Compose，结构允许日后多 Worker；不把 Agent 部署到客户生产机 |

Q3 与 Q7 合并解释：可通过已授权的只读 API/MCP/Gateway 远程取证；未提供接入条件时给人命令并等待回传。不得默认拥有目标机器访问权限。

本轮追加的明确需求：Chat 与 Admin 双面板、适合 AI 辅助开发的主流 Web 技术栈、开发机开发与便捷打包/分发/部署、插件/功能/工作流/HTML 与 Markdown 模板扩展，以及可供开发机 Codex 接手的编码就绪判断。以下 D03/D10/D11 与新增 FR13–17 据此更新。

最新明确要求：以回答质量与自主处理为核心组织能力和实施优先级。补充 FR18–20、[问答核心](../architecture/QA-CORE.md) 与[质量评测](../governance/ANSWER-QUALITY.md)；不撤销此前双面板、只读、恢复或交付要求。

## 3. 剩余事项的设计默认值

以下由用户授权采用最佳方案，不冒充用户逐题答复。可经 ADR 和影响评估调整。

| ID | 默认决策 | 理由与边界 |
| --- | --- | --- |
| D01 | 内部技术支持工程师首批使用；一个运营组织，按 customer/project/case 隔离 | 先服务内部支持流程，仍必须防客户资料串用；不做多租户 SaaS 计费/组织管理 |
| D02 | 首批验收以 WAF/SafeLine + Linux/网络常见问题为代表 | 结合已有知识资产；产品/版本由配置扩展，不把产品名称写进 Core |
| D03 | 钉钉 + REST + 完整 Chat/Admin 双面板 | 同一 React SPA；Chat 处理调查，Admin 管理连接、能力、配置、模板、账号权限与审计 |
| D04 | 优先复用已有 Dify 承载的 xmg-kb，通过检索 API 接入 | 不重复清洗/建索引；部署版本、网络、dataset 权限尚待实施联调验证 |
| D05 | V1 接一个真实 KB、真实模型、钉钉、两类只读能力 | 官方资料搜索/读取；获准产品状态或日志查询 API/MCP。真实端点未提供不得以 Fake 验收 |
| D06 | 主推理模型 + 低成本辅助模型配置；单提供方也可启动 | 按结构化输出、工具调用、中文支持、延迟和费用评测；不锁定未经现场验证的“最佳模型” |
| D07 | 主备模型可替换，但只能在同一数据授权等级内切换 | 内部模型不可失败后静默把原始客户数据送到公有模型 |
| D08 | 本地测试环境可分析日志、校验生成的诊断脚本；生产目标仅调用预注册只读能力 | 动态脚本默认交人执行；静态扫描通过不等于安全，不开任意远程 shell |
| D09 | 人工请求默认发回任务原会话及已配置支持队列 | 显示等谁、缺什么、下一步；消息失败持久记录并在 Web 显示，不虚报“已通知” |
| D10 | 答案/人工请求/报告支持版本化 Markdown 与安全 HTML 模板 | 区分已证实、推测、待验证；报告按 case ACL 下载；PDF/DOCX 后续扩展 |
| D11 | 默认最小本地登录，复用 FastAPI 官方认证组件；组织身份网关/OIDC 可选 | 便于独立部署，不自研通用身份平台；无默认管理员密码，后端角色/Case ACL/会话撤销必需 |
| D12 | 中文为默认答复语言；知识保留原文引用与版本 | 通用能力不限定中文资料，不为翻译伪造原始来源 |
| D13 | 任务结构化历史 + 摘要 + 可取回证据引用 | 摘要不替代原始证据；不默认把跨客户历史写入共享模型记忆 |
| D14 | 活跃任务不按短期 TTL 清理；已关闭任务默认保留 180 天、原始诊断附件 30 天 | 这是设计默认值，须支持组织策略/保留标记；附件到期保留摘要、hash、来源及“不可再下载”状态；不自动清理现有资料 |
| D15 | 运行护栏按 workflow 配置，不设置强制 S1–S4 产品分档 | 单执行段默认 20 步、10 分钟活跃时间、40k 总 tokens（含重试）；等待人不计入活跃时间；达到任一上限暂停 |
| D16 | 人工确认解决后 CLOSED；完整回答目标并通过检查后才 RESOLVED | 无答复不等于已解决；允许追问重开，保留历史版本；不为追求解决率自动关闭 |
| D17 | 一份源码 + 预构建应用镜像 + Compose 在线/离线包 | linux/amd64 首发；arm64 通过完整兼容测试后支持；第一 Feature 建基础打包 |
| D18 | 配置/模板热发布，代码插件与交互 UI 经构建发布 | 支持扩展不等于任意热执行代码；新节点/状态语义仍走 Feature |

## 4. 功能需求与验收映射

| ID | 必须实现的行为 | 验收证据 |
| --- | --- | --- |
| FR01 | 一问一案，SupportTask 包含目标、环境、调查、证据、状态、待办和结果 | 钉钉/REST 创建任务，查询同一 task_id |
| FR02 | 产品问题真实内部知识优先；无结果、权限失败、KB 故障有不同路径 | 三种故障注入的状态和答复不同 |
| FR03 | 证据不足选择下一获准能力；可配优先级、前置条件、升级及停止条件 | 两份产品工作流配置改变选取顺序，无 Core 代码变更 |
| FR04 | 只读目标调查；非只读动作即使被模型/Skill/人回复建议仍不能自动执行 | 未知工具、写 API、重启、任意 shell 被拒绝；生成建议不进入执行器 |
| FR05 | 暂停、补充、恢复、取消及 Worker 崩溃恢复 | 等待 72 小时等价时间测试与重启测试，保留 case/evidence/hypothesis |
| FR06 | 根据命题类别裁决冲突 | “能运行”不推出“官方支持”；旧内部手册不自动压过新版 release note |
| FR07 | 所有外发途径执行数据策略；取证与输出执行 case ACL | 敏感查询、跨客户检索、跨客户恢复与报告访问被拦截 |
| FR08 | 通用技术推理贯穿调查，能生成假设与诊断方案 | 无产品资料时给出标注的通用建议；不得编造产品结论或引用 |
| FR09 | 人工协助是持久待办，失败、回执、重试可追溯 | 通知失败不丢 HumanRequest；补充后只消费一次 resume_event |
| FR10 | Markdown/安全 HTML 报告与回答可追溯到 Evidence | 关键 claim 指向授权且真实存在的 evidence_id；保留结果/模板版本，区分未执行与已验证步骤 |
| FR11 | 支持 Provider、Skill 包和工作流版本管理 | 不兼容插件拒绝启用，进行中的 case 固定版本，升级可回退 |
| FR12 | 多任务并发、每任务单一有效执行者、投递幂等 | 重复钉钉消息、双 Worker、重复回调不会产生双结果或跨案覆盖 |
| FR13 | Chat 面板含任务、流式草稿、证据、附件、人工待办和报告；断线可恢复 | 刷新/重连不重建任务；草稿不冒充最终结果；手机可补充 |
| FR14 | Admin 含连接/能力、工作流、模板、账号权限和审计 | 后端拒绝越权；发布/回退有版本与审计，秘密不回显 |
| FR15 | 可配置主题、HTML/MD 内容与报告模板 | 无需重建镜像即可发布安全模板；旧报告不漂移；恶意模板拒绝 |
| FR16 | 可扩展 Provider、UI 页面/渲染组件及领域功能 | 配置/模板/代码边界清晰；新增已注册适配器不改 Core 厂商分支；代码扩展兼容测试通过 |
| FR17 | 可复现构建、在线/离线安装、健康检查、升级和恢复 | 干净目标主机无需 Node/源码编译；完整镜像离线导入；故障与回退有实测 |
| FR18 | 理解目标与子问题，区分直答/检索/调查/最小澄清；保留已知、未知与来源 | 通用解释不过度追问；产品事实匹配版本；多子问题不漏答 |
| FR19 | 按关键缺口选择动作，检索失败有界修正，观察后更新假设，回答前检查与有界修正 | 空结果恢复、反证、错误工具、无进展和部分回传场景产生适用下一步 |
| FR20 | 以正确性、必需事实覆盖、可行动性和合理求助验收；版本化 Prompt/模型/检索回归 | 首个真实问答阶段产出基线报告，所有关键变更跑冻结评测，指标分母完整 |

## 5. 非功能默认目标

这些是实施阶段的验收目标，不是本轮实测结果或对未知硬件的 SLA 承诺。环境基线假设：独立测试主机 4 vCPU/8 GiB 以上、外置已有 KB/LLM，不包含大模型推理及文档解析占用。

| 项目 | 目标及测量口径 |
| --- | --- |
| 接收请求 | 同区域测试环境，10 并发请求，持久化入站后 ACK/202 的 p95 < 2 秒，至少 100 次样本；不等待模型完成 |
| 简单知识回答 | 可用外部 KB/LLM 条件下，50 例的完整答案 p95 ≤ 30 秒；同时报告 provider 延迟，不用缓存冒充首答 |
| 并发 | 默认 4 个活跃执行槽，至少 100 个暂停任务；增加 Worker 无需更改业务接口；最终容量由负载测试定 |
| 故障恢复 | 测试环境 Worker 异常终止后，依赖可用时 ≤ 120 秒重新取得可恢复任务或进入明确故障状态 |
| 安全硬门禁 | 回归集中的越权取证、敏感外发、生产写执行、错误任务恢复均为 0 次；样本通过不宣称全球零风险 |
| 回答质量 | ≥100 个独立冻结人工标注案例；关键断言引用覆盖率 ≥95%，证据支持准确率/必需事实覆盖/可回答合格率/自主调查成功率 ≥90%，求助与受限答复精确率/召回率各 ≥90%；严重失真 0 次；口径见[问答质量](../governance/ANSWER-QUALITY.md) |
| 可恢复性 | 三天等待、进程重启、重复投递、旧版本恢复、部分补充全部有自动化场景；成功的业务输出不重复落库 |

## 6. V1 边界

V1 按多个 Feature 逐步完成，但发布前必须串通真实钉钉 → SupportTask → xmg-kb → 必要只读能力 → 人工补充/恢复 → 证据化答案/报告，并交付 Chat/Admin 双面板、受控模板与经过测试的在线/离线部署包。

不包含：批量知识清洗与索引、任意生产写操作、通用多 Agent 平台、低代码编辑器、完整工单/SLA 系统、Kubernetes 首发、插件市场、收费 SaaS、完整知识库管理 UI。

实际产品 API、Dify 地址/版本、可用模型、钉钉应用权限属于实施接入资料；未取得时相应任务标记 BLOCKED_INTEGRATION，可继续其他独立工作，但不得宣称真实闭环验收通过。
