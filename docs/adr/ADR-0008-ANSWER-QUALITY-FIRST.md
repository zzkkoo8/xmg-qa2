# ADR-0008：以问答质量组织核心能力与实施顺序

日期：2026-09-05；状态：本轮授权设计，待实现。来源：用户明确产品主要功能是回答问题，要求设计高质量问答 Agent、答案与自主处理能力。

## 背景与选择

既有方案已细化持久任务、Web/Admin、扩展和分发，但问答理解、检索恢复、下一动作选择、答案检查和质量评测需要同等明确的契约。保留这些支撑能力和现有开源技术栈，增加 [QA Core](../architecture/QA-CORE.md) 与[质量评测](../governance/ANSWER-QUALITY.md)。

选择显式状态图约束下的自主问答；单次 RAG 作为可快速结束的路径与评测对照，多 Agent 辩论不作为 V1 默认。低风险稳定通用解释允许显式直答；产品问题继续内部知识优先，证据不足选择下一适用能力。高优先级不代表全量执行所有工具，模型可提出动作但不能绕过策略。

## 决定与影响

- 核心成功标准为正确、切题、证据适用、可行动与合理求助；不能用引用数量、工具调用量或自动结案率替代。
- QuestionFrame、AnswerPlan、NextAction、EvidenceAssessment、AnswerDraft、AnswerCheck 为现有 Task/Evidence/结果的业务投影，不增加独立 Agent 服务或第二持久化体系。
- complete/partial/needs_input/unable_to_conclude 是答复类型；只有目标得到完整回答且通过检查才 RESOLVED，CLOSED 仍须用户确认。
- 支持有界检索恢复、按信息缺口选择只读取证、对候选答案检查和一次修正；全部共享 Run 的截止时间/预算/无进展限制。
- 第一个 Feature 建立问答控制场景与评测结构，第二个真实 KB/模型 Feature 交付答案质量基线，之后扩展自主调查、入口与个性化。完整 Web、Admin、模板与分发仍属 V1，不删除已确认需求。

兼容增补需求 FR18–20 和 Constitution 1.2.0；补充 ADR-0003/0005/0006/0007，不改变目标只读、数据外发、任务恢复和 Git 门禁。尚无运行时产物，不需要现有数据迁移；未来 Feature 须冻结新增 Schema 与旧任务版本兼容。此设计修订与推送不授予业务编码或部署权限。
